### The design, in one paragraph

`hubSession({ getter, onFault, overrides, log, raise, isAlive, retries, ops })` owns three rules:
**FRESH ALWAYS** (a restore replaces the hub file mid-tick, so a handle taken earlier can be an
unlinked inode), **NO HANDLE NO OPERATION**, **SAID ONCE**. Its surface is `read`, `sayFault`,
`available`, `perform`, `release`, `noteCooldown`, `drainRetries`, and it is **frozen**.
`perform(name, fallback, args, whenAbsent)` acquires a handle, uses it once, and **never returns
it** — that is what makes the rules unskippable rather than conventional. `hub()` and `hubOr()`
were deleted once nothing used them: a dead method returning a raw handle is an invitation.

**What the session deliberately does NOT own:** the arguments each operation is called with, and
each caller's answer to *"there is no scheduler right now"*. Those answers are not
interchangeable — housekeeping skips, a release **defers**, a claim **fails open** — and a
session that chose for them would be deciding policy it cannot see the reason for. All 12 sites
state their own, verified 12 of 12.

### The acceptance test took FIVE formulations

Four passed while the defect was present. Keep these:

1. *"is this handle one the getter ever handed out?"* — a **retained** handle is still in that set.
2. *"is it from the most recent acquisition?"* — a retaining session **stops asking**, so the most
   recent acquisition becomes the retained one. **The instrument's baseline moved with the defect
   it was measuring.**
3. and 4. the stub never reached the path it claimed to break.

The working form anchors to the **fixture's own clock**: it replaces the hub underneath a running
tick at a moment it chooses, and nothing the tick does can move that. The file carries its
**negative control first** — a deliberately retaining session the same reading must catch.

### What landed, and the design decisions inside it

**`src/build/capabilities.mjs`** — `CAPABILITY_KEYS` is **derived from `FIELDS`**, never listed.
The failure mode is the invisible one: `leaseEffect` refuses unless a capability is exactly
`true`, so a typo in a key string reads as *"capability off"* — fail-closed, nothing red.

Two controls, both the peer lane's insistence and both earned:
- **the derived set is non-empty.** Deriving alone is not enough: an import that silently yields
  nothing makes every assertion over it pass **vacuously**. *The count is the control.*
- **a sixth key is noticed.** The count is pinned, so adding a switch fails and the person adding
  it is told to cover it.

**`capabilitiesFrom` preserves ABSENCE.** Codex caught this and it is worth keeping in mind:
`leaseEffect` reads the map twice — it gates on `!== true` (absent and false identical, correct)
and then writes a **different `last_error`** for each. Filling every key with `false` collapses
*"never enabled"* and *"turned off"* into one, and that line is the only signal an operator has.
**My test asserted the defect**: it required every key present AND false, which *is* the collapse,
under a comment claiming the distinction survived.

**`builder.budgets` is ONE key, not eighteen** — a property of the validator, not a style choice.
`validate`'s unknown-key sweep waves through any leaf beneath a declared key, so declaring the
sub-fields would make `builder.budgets.BUILD_NOPE.budgetMinutes` a valid leaf. **The names are
refused inside the validator or they are not refused at all.**

**`BUILD_ACTION_FOR` lives in `src/build/phases.mjs`** and is **encoded, not derived**: phase
`SIZING` dispatches as `BUILD_SIZE`, not `BUILD_SIZING`. A `BUILD_${phase}` rule is right for two
of three and **wrong for the one nobody would check** — worse than an honest map because it looks
principled. The half that *can* be checked is, in **both directions**: every key is a real phase,
and `BUILD_ACTIONS` is exactly the map's values.

## 8. The findings that matter beyond their fix

**A completed plan is evidence about the plan.** I reported #50 done because its six-PR plan
finished. The plan was narrower than the issue: one of four rules had moved. Check work against
the thing it was meant to satisfy, not against the schedule for satisfying it.

**An instrument that reads DIFFERENCE as signal needs its baseline proven stable first.** A
coverage sweep reported "0 of 14 sites unwatched" while one scenario was **non-deterministic** —
it differed from itself every run, so every stub looked effective. Every sweep now asserts the
baseline and refuses to report otherwise. *Variance and effect are the same reading.*

**A test that HANGS is worse than one that fails.** Removing the heartbeat made a fixture await a
beat that never came, with no bound. It reports nothing, "no answer yet" is indistinguishable
from "still working", and it silently truncated a sweep — three sites went unmeasured.

**A stub that misses its path reports GREEN; a stub that makes the code THROW can report as
"nothing moved".** Three of five acceptance-test formulations failed for the first reason. One
coverage sweep under-reported for the second. **Always check the stub reached the path.**

**An escape whose output a valid input can SPELL is not an escape.** `safePath` escaped control
bytes to `\xNN` and left the backslash alone: `b\x01.t` — four ordinary characters — rendered
identically to a name containing byte `0x01`. Fixed in #77. The peer had the same defect in their
own `displayPath`, written independently. **Two people solved "render a byte path safely"
separately and both got it wrong the same way** — that is design evidence, not coincidence.

**The second-inventory class was found FOUR times in two days:** the capability keys,
`TABLES_AT`/`COLUMNS_AT` (issue #43, still open), the two `displayPath`s, and `BUILD_RESEARCH` in
`sandbox.mjs`. When two places must agree, derive one from the other and assert the derivation is
non-empty.

**Absence and "turned off" are different facts.** Collapsing them destroys the only signal an
operator has. So is *"no unresolved threads"* versus *"no threads at all"* — a PR nobody reviewed
is not a PR whose review is clear.
