you are executing.**

## 9. How to work here

- **The four-check stub loop on every fix:** control green → stub proven by a **HASH CHANGE, not
  a grep** → the RIGHT assertion red → restore **byte-identical by file copy, never
  `git checkout`**.
- **Compare the stubbed run's ASSERTION COUNT against the control's.** A stub that throws aborts
  the file, and a truncated run looks exactly like the missing assertions passing. This bit
  three times.
- **A stub that produces no failures means the property is UNTESTED.** Twice a stub of mine made
  the code *stricter*, which nothing can observe. An entry that cannot go red is worse than no
  entry, because it reads as a guard.
- **Every new test file needs a manifest entry**, and **a grandfathered file loses grandfathering
  the moment you MODIFY it**.
- **Run `node test/anchors-resolve.test.mjs`** — 107 anchors in 8ms. It caught five rotted
  anchors of mine before they left the machine.
- **Verify merges by CONTENT:** `node scripts/verify-merge.mjs <pr>`; check `merged-head` equals
  `branch-now`. Four fixes were silently dropped this way in one day.
- **Full suite** excludes `test/escape.test.mjs`, with a `fail=0` accumulator. **Baseline: 116
  files, 0 red.** CI runs `npm ci && npm run lint` BEFORE the suite; a fresh worktree needs the
  install.
- **`$?` after a pipe or a `$(…)` is not your command's status.** I reported `exit=0` for a run
  that exited 1 because `$(basename $f)` reset it.
- **Generate string literals, do not hand-escape them.** Three attempts at writing a JS string
  containing a regex failed; `JSON.stringify` of the real source line worked first time.
