## 3. Why main is red, and why it is not this lane's doing

`main` has been red since **11:53Z**, when **#115** landed a stricter sweep verdict:
*a stubbed run shorter than its control is no longer a reading*. Nothing regressed —
the instrument learned to see, and **four pre-existing entries became visible**.

    11:28:24Z  92ce25c  success    <- last green main
    11:53:05Z  f388dca  failure    <- #115 merged here
    ... every run since: failure

- `premerge-binds-the-verified-head` — fixed by the guardian lane in **#122**.
- `taskfile-dry-run-writes-nothing` — **fixed on #110**, ran 104 of 122 assertions.
- `artifact-write-is-atomic-against-a-crash` — **fixed on #110**, 22 of 182.
- `artifact-expect-needs-no-depth` — **fixed on #110**, 124 of 182.

**All three are one mechanism, and it is the most transferable thing in this
handoff: the stub does not make an assertion FAIL, it makes a call THROW.** A throw
kills the file, so every assertion after it never runs — and an assertion that never
ran reads in the log exactly like one that passed.

The fix: helpers return `ok: null` on a throw. Neither `true` nor `false`, so
whichever direction the consuming assertion tests, it goes red. Both files now run
to completion under their stubs (187/187 and 122/122).

**Where the shelter is deliberately NOT applied:** the control asserting that a
partial write really failed calls `writeArtifact` directly. Wrapped, it would have
reported the write as succeeding — *the shelter that keeps a stubbed run alive must
never be applied where the exception is the thing being measured.*

**So #110 takes main green with it.** Two lanes are blocked behind that.

## 5. What #110 actually contains, and the rules it established

23 commits. Original scope was nine findings deferred from T4; it grew to ~35 fixes
across six review rounds, every finding real. Highlights that carry rules:

**A regex cannot pair fences.** Four defects in one expression, each fix narrower
than the last: bare fences let four backticks close on three; a backreference was
defeated by BACKTRACKING; narrowing the info string fixed that; then an empty block
matched starting at its own CLOSER. The fourth attempt is a line SCANNER. *A rule
needing a more specific pattern every time it is corrected is being enforced by the
wrong mechanism.*

**The recorded schema version is not a loop bound.** `historyGaps` enumerated to the
maximum in `schema_version` — a table an operator hand-edits. Measured: a hub whose
only row is `1000000000` killed the process with a V8 heap OOM. Split into
`hasHistoryHole` (counts, cannot be made expensive) and `historyGaps(versions, upTo)`
(names them, refuses a bound above `HUB_SCHEMA_VERSION`).

**Five faults, five remedies.** The hub guard now classifies: unreadable → NEWER →
INVALID marker → HOLED → missing TAIL. Each takes a different repair; the original
named one remedy for all of them, and `openHub` refuses three of the five.

**A read-only SQLite open still writes.** Measured: it creates `-wal`/`-shm` and
leaves them. `immutable=1` removes them and was measured WRONG — with a live writer
holding the WAL it reads the main file alone and reports a healthy hub as
`no such table: schema_version`. **It does not go stale, it goes blind.** So the
promise is stated for what it covers (CONTENT and SCHEMA), and the boundary is an
assertion rather than a comment.

**The gate refuses to guess.** The RESEARCH skip branch was unreachable TWICE —
first keyed on `expect.depth`, then on `expect.skipped`, and S3-D's
`researchExpectations` carries neither. Rather than guess a third field, an
expectation carrying neither is REFUSED, naming the field the helper must carry.
That turns the contract from aspirational into enforced.

**Sweep entry rules learned the hard way, all measured:**
- `if (false && A || B)` is still true — the mechanical `false &&` insertion is
  unsound past a top-level `||`. Audited: 113 replacements, 0 other instances.
- One entry covering TWO properties names only one → `WRONG_RED`. Split it.
- A stub that does not parse is `CRASHED`, not `CAUGHT` — that precedence matters.
- Stubbing one side of a two-sided comparison is a DIFFERENT defect. On macOS `/var`
  is a link to `/private/var`, so a half-stubbed path comparison refuses everything.

## 8. How to work here

- **The four-check stub loop on every fix:** control green → stub proven by a HASH
  CHANGE not a grep → the RIGHT assertion red → restore byte-identical by file copy,
  never `git checkout`.
- **The sweep now checks assertion counts itself** (#115), so the scratch checker I
  was running beside it is retired. Trust the sweep's verdict.
- **`test/stub-manifest.mjs` conflicts on nearly every PR.** Take `origin/main`'s copy
  WHOLE, re-append your own by NAME, and **re-apply your own MODIFIED entries** —
  taking the copy whole silently reverts those. Verify in BOTH directions: no entry
  of main's missing OR altered, none of yours missing, none of your modifications
  reverted, no duplicates, and `GRANDFATHERED` **byte-identical** to main's. A count
  sees none of those failures.
- **`GRANDFATHERED` may only shrink.** It went 98 → 96 today
  (`hub-gatestate`, `repo-id-lookup`).
- **Run `node test/anchors-resolve.test.mjs` after EVERY manifest edit** — 169 anchors
  in ~20ms. It caught anchor rot repeatedly today.
- **Never run the suite while the sweep is running** — the sweep mutates the tree and
  the suite will measure a stubbed file.
- **Verify merges by CONTENT:** `node scripts/verify-merge.mjs <pr>`.
- **`$?` after a pipe or a `$(...)` is not your command's status.**
- **Generate string literals with `JSON.stringify` of the real source line**; do not
  hand-escape them.
