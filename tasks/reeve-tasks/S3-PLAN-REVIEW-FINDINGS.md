# S3-A and S3-B — adversarial pre-review findings, 2026-08-28

**What this is.** A pre-review of the two plan documents that land first, run before either
went to a PR. Six lenses, each drawn from a failure class this repository has actually measured,
and every finding then handed to a refuter told to **default to refuted when uncertain** and to
confirm only what it re-ran itself.

**55 findings raised, 38 survived refutation** — the 17 that died are not listed, which is the
point of the refutation pass. Almost every survivor was confirmed by *executing* the plan's own
code against the real source at `16cd880`, not by reading it.

**Why this was worth doing.** The measured density for plan PRs in this repository is 46–70
findings per 1,000 lines. S3-A and S3-B are 4,164 lines, which projects to roughly 190–290
findings across their review rounds. Twenty-three P1s found before the first round is that many
rounds not spent.

**Neither document is ready to land.** Work these first.

## The shapes, which matter more than the individual findings

**`stub-loops` — 10 findings, and this is the headline.** The four-check stub loop is the
discipline this whole programme rests on, and ten of them in two documents **cannot be run as
written**: loops that restore from a `.bak` the plan itself has already deleted; a stub whose
"verified applied" grep reads 1 only while the stub is *not* applied; stubs where neither named
assertion can go red; a stub whose anchor text does not exist in the function the same task
ships. *A stub that produces no failures means the property is untested* — and here the stub
could not produce a failure because it could not run.

**`consistency` — 10 findings.** The family disagrees with itself about names it shares:
`registryProjects` is imported from a module that never exports it; `registryIo` is called with
one options object where it ships with four positional parameters; `capabilitiesFrom` is
consumed as short keys and shipped as dotted profile paths, and **S3-B's own test hides the
mismatch because its fixture hand-writes the short-key map instead of calling the real
function**.

**`interfaces` and `runnable` — 14 findings**, several of which mean an executor following the
plan literally reaches Step 4's *"expect all green"* on a file that is red.
