## 4. Decisions taken during these stages — do not re-litigate

1. **Native OS sandbox with fail-if-unavailable and no unsandboxed fallback.** A host whose
   sandbox is unavailable dispatches nothing. *2026-08-21.*
2. **A scratch HOME**, after the keychain measurement (§2). And the sharpened version, recorded
   because the first statement of it was too strong: **a scratch HOME closes the keychain
   *search list*, not the keychain** — the file stays reachable by path until
   `~/Library/Keychains` is denied. *2026-08-22, corrected the same week.*
3. **`--setting-sources ""`, `--safe-mode`, `--strict-mcp-config`, `--no-chrome`**, explicit
   tools and agents, settings validated **before** spawn. *2026-08-21.*
4. **Fail-closed `onSpawn`.** If binding the spawned process fails, the group is killed and the
   run records `UNBOUND`. S3's T6 re-asserts this at the builder seam. *2026-08-21.*
5. **`worker_run` is additive.** No existing guardian table changes shape. *2026-08-21.*

## 5. The durable findings

**The durable finding is that a permission rule takes an absolute path only with TWO leading
slashes.** `Read(/Users/x/.ssh/**)` matches **nothing**, silently, and a rule that matches
nothing is indistinguishable from a rule that is working
(`docs/measured/2026-08-22-the-read-deny-list-was-inert.md`).

**The durable finding is that the file tools are not covered by the OS sandbox.** The CLI's own
process runs outside the Seatbelt profile it applies to the shells it spawns. Never argue that
a file is protected because a worker is sandboxed.

**The durable finding is that a deny which *contains* the worker's checkout refuses the worker
its own files**, because deny beats allow.

**The durable finding is that a restriction can live beneath reeve's own declarations.** The
`.git` write block that stopped three dispatches dead is the CLI's sandbox layer, **below**
reeve's settings — reeve's settings carry `denyWrite: []` and deny `.git/**` only for
Edit/Write/NotebookEdit. The worker spent **thirteen consecutive tool calls** correctly
diagnosing an impossible instruction. **Treat any dispatch failure that looks like a permission
problem as a layer question, not a grant question.** S3's T7 extends the canary to probe the
three capabilities it has never probed — `Agent(*)`, `WebSearch`, `WebFetch`.

**The durable finding is that `pull_request.updated_at` does not change when a review thread is
resolved.** It is blind to review state and must never be a change signal or an ordering
(`docs/measured/2026-08-22-the-shadow-compared-two-moments.md`).
